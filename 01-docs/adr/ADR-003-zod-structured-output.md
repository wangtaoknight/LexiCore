# ADR-003：AI 输出必须过 Zod 校验，绝不写未校验数据

- 状态：Accepted
- 日期：2026-11

## 背景

所有 AI 结果都要落库并进入人工审核流程。模型偶尔会：包一层 ```json 围栏、在 JSON 前后加解释、字段多/少、枚举值写错（如把 `high` 写成「高」）、内容超长。若直接把原始文本入库，脏数据会污染版本历史。

## 决策

统一走 `server/ai/structured.ts` 的 `requestStructured()`：

1. 以 `response_format: {"type":"json_object"}` 调用模型；
2. `parseJsonLoose()` 宽松解析（直接 parse → 去围栏 → 截取首个 `{` 到末个 `}`）；
3. 用 `server/ai/schemas.ts` 的 **Zod schema** 严格校验（含长度上限、枚举、数组条数、数字范围）；
4. 校验失败 → 带上校验错误清单做**一次**「修复为合法 JSON」调用；
5. 仍失败 → 抛 `upstreamError`，任务失败，**不写库**。

## 备选方案

| 方案 | 放弃原因 |
| --- | --- |
| 只在 prompt 里要求「输出 JSON」 | 实测仍会偶发围栏与多余文字，无法保证入库质量 |
| 用 `JSON.parse` + 手写字段检查 | 校验逻辑分散，错误信息不可读，模型难以据此自我修复 |
| 多次无限重试修复 | 成本不可控，且模型陷入同一错误时会死循环 |

## 后果

- **正面**：数据库里只有「结构合法」的内容；校验错误可回填给模型自我修复；schema 同时是前后端字段的接口契约。
- **负面**：一次失败会多花一次调用；schema 变更需同步前后端（`client/src/ui/fields.ts` 的字段定义）。
- **约束**：修复只做一次，之后必须失败，避免静默劣化。
