# 项目名称：英语词汇概念研究与审阅系统

## 一、项目目标

请帮我建立一个网页软件，主要用于英语六级词汇的深度研究和学习。

这个软件与传统背单词软件不同。它不以记忆英文单词及其中文翻译为核心，而是以理解单词背后的具体概念为核心。

基本理念：

一个英文单词可能包含多个不同的意义，每个意义都应该被视为一个独立的概念和学习对象。

我们需要研究的是：在英文世界中，这个单词在特定语境下究竟表达什么概念，它的准确含义和适用边界是什么，与中文概念有什么区别，与其他近义词有什么区别。

通过 AI 协助研究，再由人工逐项审核、修改和确认，最终形成准确、可靠、可以持续积累的个人词汇知识数据库。

本项目首先实现概念研究和人工审阅功能，暂时不需要开发传统的背单词、考试测试和间隔复习功能。

## 二、核心工作流程

用户在输入框中输入一个英文单词，软件调用配置好的 AI API，对该单词进行全面分析。

AI 返回结构化的研究结果，网页将其展示出来。

所有 AI 生成的内容默认处于「待审核」状态，不能直接成为正式知识。

用户可以对每一项内容进行：

1. 通过：认可该内容，存入正式数据库。
2. 驳回：认为该内容不准确，并填写修改意见。
3. 重新分析：AI 根据原始问题和人工意见重新分析，给出新的结果。
4. 人工编辑：用户可以直接修改 AI 的结果。
5. 再次审核：修改后的内容仍然需要人工确认。

必须支持针对单个词义、单条例句、单个近义词等具体内容进行独立审核，而不是只能整体接受或整体拒绝一个单词的分析。

已审核通过的内容不得因为其他部分重新分析而自动被覆盖。

## 三、单词分析结构

每输入一个单词，AI 应当按照以下结构生成研究结果。

### 1. 单词基本信息

- 英文单词。
- 音标。
- 词性。
- 词汇基本信息。
- 词源和历史演变的简要说明。
- 如果存在明确的核心意义，给出核心意义。
- 如果多个义项之间没有可靠的共同核心，不得强行归纳。

### 2. 单词的完整义项梳理

尽可能梳理现代英语中具有实际使用价值的不同义项。

每个义项单独建立一个研究单元。

每个义项需要提供：

**A. 基本信息**

- 义项编号。
- 词性。
- 中文参考译法。
- 英文释义。
- 该义项的使用频率：高频、中频、低频。
- 六级考试相关重要程度。

**B. 概念解释**

这是整个系统最重要的部分。

需要准确解释这个单词在当前义项下，在英语世界中究竟表达什么概念。

要求：
- 不要简单地使用几个中文字代替概念解释。
- 要解释该词所描述的具体对象、行为、状态、关系或者现象。
- 明确其适用范围和意义边界。
- 说明容易产生的误解。
- 解释其与中文对应概念之间的联系和区别。
- 必要时给出具体场景，帮助用户理解。

**C. 词义历史**

- 这个义项是如何产生和发展的？
- 是否存在从其他义项演变而来的关系？
- 如果存在明显的语义变化、隐喻、转喻或者有趣的意义转变，应当重点说明。
- 如果与其他义项没有明确的历史联系，应当如实说明。

注意区分词汇的历史词源与词义的历史演变。

### 3. 例句研究

针对每一个义项，提供能够准确体现该义项的英文例句。

来源优先级：

1. 大学英语四级、六级真题。
2. IELTS 真题及官方学习材料。
3. 可靠的英语语料库。
4. 英美影视剧台词。
5. AI 根据准确概念生成的例句。

每条例句包括：

- 英文原句。
- 中文翻译。
- 该句表达的具体含义。
- 重点词汇和搭配。
- 来源名称及链接（如有）。

严格禁止把 AI 生成的句子冒充成真题原句或者影视剧原台词。

无法验证来源时，必须注明「AI生成例句」或「来源待核实」。

### 4. 固定搭配研究

针对当前义项，整理常见固定搭配。

每个搭配包括：

- 英文搭配。
- 中文含义。
- 具体使用条件。
- 对应例句。
- 例句来源。

固定搭配必须与当前义项相匹配，不能把其他义项下的搭配混入。

网页展示时，固定搭配应使用加粗、颜色或其他明显方式突出。

### 5. 同义词研究

整理与当前义项在意义上接近的英文单词。

每个同义词需要提供：

- 单词。
- 核心含义。
- 与当前词义的共同点。
- 具体区别。
- 适用场景。
- 是否可以互换，以及不能互换的情况。

不能仅仅罗列一组中文意思相近的单词。

重点是帮助用户理解不同英文概念之间的边界。

### 6. 反义词研究

整理当前义项对应的反义词。

每个反义词包括：

- 英文单词。
- 核心含义。
- 与当前义项的对立关系。
- 具体区别。
- 典型使用场景。

如果不存在准确的反义词，允许注明「没有直接对应的反义词」，不得为了完成栏目而强行编造。

### 7. 频率及重要程度

每个义项单独评定：

- 高频。
- 中频。
- 低频。

同时给出六级考试的重要程度。

需要区分一般英语使用频率和六级考试中的重要程度，不能将两者混为一谈。

尽量根据可靠语料、词频表和考试材料确定。无法获得客观数据时，应明确标注为 AI 估计。

## 四、人工审核系统

这是软件最重要的交互功能之一。

AI 生成的每一项内容都需要有独立的审核按钮：

- 通过
- 驳回
- 修改
- 重新分析

用户驳回时，可以填写具体意见。

例如：

「这个概念解释过于宽泛，没有说明与另一个近义词的区别。」

AI 应当根据该意见重新研究，并输出修改后的结果。

要求：

1. 保留之前的 AI 分析记录。
2. 保留用户的驳回意见。
3. 显示新旧版本的区别。
4. 用户可以再次审核。
5. 已经审核通过的内容不会被其他分析自动修改。
6. 用户可以主动解除通过状态，重新审阅之前的内容。

每一项内容必须具有独立审核状态。

建议的状态包括：

- 待审核
- 已通过
- 已驳回
- 重新分析中

最终，只有人工通过的内容才正式进入个人知识数据库。

## 五、数据库设计

需要建立可以长期积累、查询和维护的数据库。

建议采用以下层级：

单词 Word
→ 词义 Sense
→ 词义解释 Definition
→ 例句 Examples
→ 固定搭配 Collocations
→ 同义词 Synonyms
→ 反义词 Antonyms
→ 历史演变 History
→ 审核记录 Review History

一个单词可以有多个词义。

一个词义可以有多条例句、多个固定搭配、多个近义词和反义词。

每一条具体内容均需要保存：

- AI 原始生成结果。
- 人工修改结果。
- 审核状态。
- 审核时间。
- 人工意见。
- 版本记录。
- 相关来源。

需要支持按照单词、词义、词性和审核状态进行查询。

还需要支持数据导出，避免未来更换软件时丢失已经积累的研究结果。
每一条内容不只是标记高、中、低频率，还要标记证据类型：
标记	含义
已验证	有可靠词典或语料来源
有来源	有可追溯来源，但仍需人工判断
AI推断	根据已有知识生成，未找到直接证据
待核实	目前存在争议或信息不足

但数据库最好预留未来字段：
- 用户对某义项的掌握程度。
- 最近一次复习时间。
- 复习次数。
- 错误记录。
- 例句理解情况。
- 是否能够主动运用。
这样未来增加记忆训练时，不需要推翻前期积累。

## 六、AI API 接入

软件应当支持连接外部 AI 模型 API。

用户可以配置：

- API Key。
- API Base URL。
- 模型名称。
- 其他必要的请求参数。

AI 调用应当通过后端完成，不得将 API Key 暴露在浏览器前端代码中。

需要支持：

- 单词分析。
- 指定义项重新分析。
- 根据人工意见修改分析结果。
- 增加例句。
- 增加近义词和反义词。
- 对指定内容进行进一步解释。

每项任务应当能够独立调用 AI，避免重新分析一个小模块时重复生成整份单词报告。

AI 返回结果采用结构化数据，方便网页展示和数据库保存。

## 七、网页界面

整体界面应当简洁、清晰，突出内容研究和人工审阅。

主要页面：

**1. 首页**

- 单词输入框。
- 搜索和添加单词。
- 已研究单词数量。
- 待审核内容数量。
- 已完成研究的单词列表。

**2. 单词研究页面**

- 单词基本信息。
- 核心意义。
- 词源和历史演变。
- 全部义项列表。
- 每个义项的完整研究内容。
- 例句、固定搭配、近义词、反义词。
- 每项内容的审核操作。

**3. 审核页面**

- 待审核内容列表。
- AI 原始结果。
- 用户审核意见。
- 新旧版本对比。
- 通过或驳回。

**4. 数据管理页面**

- 全部已研究单词。
- 已通过的词义。
- 未完成的研究。
- 数据导出。
- API 配置。

## 八、开发原则

1. 优先实现完整、稳定的概念研究和审核流程。
2. 不要将软件设计成传统背单词软件。
3. 不要追求复杂的动画和装饰性设计。
4. 所有 AI 生成内容均应当可编辑、可审核、可追溯。
5. 数据库必须支持长期积累，不能只在页面中临时显示 AI 回答。
6. 前后端分离，模块化设计，方便后续增加记忆训练功能。
7. 优先保证数据准确性、审核效率和操作体验。

请先完成产品结构、数据库结构、页面设计和 AI 调用流程，再进行具体开发。
