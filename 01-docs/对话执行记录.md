# 对话执行记录（Worklog）

> 用途：逐轮记录与 AI 协作的**执行过程**，便于回溯「谁、什么时候、为什么改了什么、怎么验证的」。
>
> 与 `CHANGELOG.md` 的分工：`CHANGELOG.md` 记**产品变更**（面向版本与用户），本文件记**协作过程**（面向对话与决策现场）。

## 维护约定

1. 每轮对话结束后追加一条 `R-xx`，只写事实，不写推测；未验证的内容标注 `未验证`。
2. 路径统一写相对**仓库根目录**的路径（2026-11-20 之后代码位于 `02-code/`）。
3. 「诉求」尽量保留用户原话（可截断），便于还原真实意图。
4. 「诊断」写根因，不写过程猜测；「改动」只列最终落地的文件。
5. 每条控制在 5–8 行，细节留给 `adr/` 与代码。

```md
### R-xx 标题（YYYY-MM-DD）
- **诉求**：
- **诊断**：
- **改动**：
- **验证**：
- **遗留**：
```

- **改动**：`02-code/server/**`（db/、repositories/、services/、routes/、ai/）、`02-code/client/**`、`02-code/server/db/migrations/001_init.sql`（words / items / item_versions / review_events / ai_tasks / settings / learning_meta）、`02-code/scripts/ensure-sqlite-prebuild.js`。

### R-02 「测试连接」总是失败（2026-11-15）

- **诉求**：设置页点「测试连接」显示连接失败。
- **诊断**：不是 Key 问题，而是 Node 网络层失败（`fetch failed`）。Node 不读系统代理，报错信息只显示 `fetch failed`，无法判断是 DNS、代理还是 TLS。
- **改动**：`server/ai/client.ts` 增加 `describeNetworkError()`（区分超时 / DNS / 拒绝连接 / 证书），并把重试改为 4 次、1s→2s→4s 退避；`README.md` 增加排查章节。
- **验证**：用假 Key 请求实际返回 401（说明网络通）、4 次后端测试耗时 559–875ms。
- **遗留**：代理场景仍需用户自行设置 `HTTPS_PROXY`（已写入 README）。
